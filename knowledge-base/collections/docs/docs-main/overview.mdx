# Visão Geral da Arquitetura

O **Academic Lab** opera sob uma estrutura monorepo orquestrada com **pnpm Workspaces** e
**Turborepo**. Essa abordagem permite reutilizar configurações, tipagens TypeScript e componentes
entre diferentes aplicações com cache inteligente e paralelização de tarefas.

---

## Mapa do Monorepo

O repositório está subdividido em três grandes contextos limitados (_Bounded Contexts_):

```plaintext
academic-lab/
├── config/                      # Configurações globais e tipos TypeScript
├── knowledge-base/              # Portal de documentação e conteúdo acadêmico
│   ├── apps/main/               # Aplicação web Docusaurus 3
│   ├── collections/             # Coleções puras de documentação e blog
│   │   ├── docs/docs-main/      # Documentação técnica (Diátaxis)
│   │   ├── docs/community-main/ # Diretrizes de colaboração e roadmap
│   │   └── blogs/blog-main/     # Artigos e notas científicas
│   └── packages/                # Bibliotecas compartilhadas da plataforma
│       ├── preset/              # Preset dinâmico para coleções Docusaurus
│       └── theme/               # Tema estilizado e tokens visuais com Tailwind v4
└── .agents/                     # Automação por agentes, skills e plugins MCP
```

---

## Responsabilidades dos Pacotes

A tabela a seguir descreve a separação de responsabilidades no ecossistema
`@tupynambalucas/academic-lab`:

| Pacote                      | Caminho                           | Responsabilidade Primária                                               |
| :-------------------------- | :-------------------------------- | :---------------------------------------------------------------------- |
| `@academic-lab/config`      | `config/`                         | Fonte única da verdade para dados do pesquisador, metadados e Prettier. |
| `@academic-lab/collections` | `knowledge-base/collections/`     | Repositório de conteúdo puro em `.mdx`, totalmente desacoplado da UI.   |
| `@academic-lab/preset`      | `knowledge-base/packages/preset/` | Preset do Docusaurus que resolve coleções dinamicamente por nome.       |
| `@academic-lab/theme`       | `knowledge-base/packages/theme/`  | Camada de estilo com tokens Infima e utilitários modernos Tailwind v4.  |
| `@academic-lab/app-main`    | `knowledge-base/apps/main/`       | Aplicação executável do portal Docusaurus que consome os pacotes acima. |

## O Fluxo de Resolução Dinâmica de Coleções

Diferente de instalações padrão do Docusaurus onde o conteúdo precisa residir dentro da pasta da
aplicação, o preset `@academic-lab/preset` intercepta a configuração do `docusaurus.config.ts`:

```typescript
// knowledge-base/apps/main/docusaurus.config.ts
presets: [
  [
    require.resolve("@academic-lab/preset"),
    {
      docs: [
        {
          id: "default",
          collection: "docs-main", // Mapeado para knowledge-base/collections/docs/docs-main
          routeBasePath: "docs",
        },
      ],
      blog: {
        collection: "blog-main", // Mapeado para knowledge-base/collections/blogs/blog-main
        routeBasePath: "blog",
      },
    },
  ],
];
```

Esse mecanismo desacopla totalmente quem escreve o conhecimento científico de quem mantém a
infraestrutura do site, viabilizando a inclusão de novas coleções de matérias, pesquisas e artigos
com zero atrito de engenharia.
